How do I approach designing software?
My approach to software design is rooted in rigorous upfront planning and structured visualization. While designing the 3D minimalist workstation scene, I learned to carefully map out 3D coordinate systems and plan the necessary matrix transformations before writing a single line of code. Crafting this project helped me develop new skills in spatial reasoning and translating physical concepts—like a textured wooden desk and a coffee mug—into mathematical models using C++ and OpenGL.

The design process I followed involved defining the requirements of the scene, calculating the vertices and indices for the geometric shapes, and mapping out how textures and complex lighting would interact within the environment. I often rely on structured documentation for systems analysis, and applying that same level of deliberate planning to graphics rendering ensured the scene came together smoothly. These tactics of thorough architectural planning and mathematical mapping are universally applicable to future work, whether I am designing a user interface, mapping out a network topology, or structuring a secure cloud environment.

How do I approach developing programs?
Developing the 3D scene required a highly iterative development strategy. Working with OpenGL means you cannot simply write the code top-to-bottom and expect a perfect render on the first compile. I utilized iterative cycles—much like Agile methodologies—to build the project incrementally. I started by generating basic geometry, tested the camera controls, applied the wood and ceramic textures, and finally layered in the complex lighting.

Iteration was the core of my development process. If the lighting behaved unexpectedly on the coffee mug, I would isolate the shader code, adjust the ambient and diffuse variables, and re-compile. Throughout the milestones, my approach to developing code evolved from simply focusing on syntax and compilation to prioritizing modularity, memory management, and visual accuracy. Breaking the project into manageable, testable components ensured that the final rendering was both stable and visually cohesive.

How can computer science help me in reaching my goals?
Studying computer science, and specifically tackling computational graphics, provides a deep understanding of how software interacts directly with hardware. Educationally, working with C++ and OpenGL forces you to manage memory manually and understand low-level system operations. This foundational knowledge is crucial for my broader educational pathway, as it strips away the abstractions of high-level languages and exposes the core mechanics of computing.

Professionally, my goal is to become a Cloud Cybersecurity Architect. While 3D visualization might seem distant from security, the underlying principles are highly relevant. Understanding memory management, low-level system interactions, and secure coding practices in C++ is vital for identifying system vulnerabilities—similar to the assessments required for securing web interfaces or corporate network infrastructures. Grasping these complex, low-level technical concepts directly supports my professional trajectory and will be instrumental as I work toward industry-standard certifications like CompTIA Security+ and CISSP.
